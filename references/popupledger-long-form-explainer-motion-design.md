# PopUpLedger Long-Form Explainer Motion Design Playbook v3.0

## Goal
Create explainers that feel like a designed editorial production rather than a slideshow of generic AI video clips. The edit combines clear narration with visual evidence, animated explanations, relevant real footage, contextual graphics, and deliberate sound design.

## Required first steps
1. Read the script and listen to the actual narration if available.
2. Identify the hook, definitions, claims, examples, mechanisms, comparisons, quantitative facts, exceptions, emotional beats, and conclusion.
3. Run the project's creative-direction mode if not already selected.
4. Inspect reference videos when possible and honestly note inaccessible/unverified references.
5. Create a design bible, beat map and asset/source manifest.
6. Inspect available rendering tools before planning exact effects.
7. Build and inspect a 30–60 second representative section where feasible before extending complex graphics across the full video.

## Visual choice logic
- A mechanism/process → progressive diagram, cause/effect chain, sequence or animated object model.
- Comparison → aligned split-screen, before/after, comparison table or synchronized states.
- Numeric claim → factual chart/counter/ratio with exact unit/date/source. Don't animate a count as if it changes through time if it is only a static total.
- Historical sequence → grounded timeline with sourceable images and restrained labels.
- Location/journey → grounded map or route, plus real geographic footage when useful.
- Software/product interface → genuine screen capture, crop, mask, cursor focus and tracked highlight.
- Document/citation/claim → actual source excerpt or document plus a concise attribution label.
- Abstract concept → designed illustration, metaphor, node map or restrained animated shape system.
- Human impact/emotion → authentic footage, sourced photo, relevant interview/presenter or clearly illustrative AI clip; preserve sincerity.
- A light transition between ideas → clean cut, match, mask or shape transition only when movement or form connects the ideas.
- A small point worth emphasizing → contextual pop-up/callout, not an entire explanatory card.

## Quality principles
- Visual motion should reveal a relationship or direct attention; it should not be a random event behind narration.
- One primary message per designed frame. Keep secondary labels concise.
- Build a model in semantic order: anchor → component → relationship → consequence → complete model.
- Keep exact text/data in editable/native text or SVG/HTML; never rely on generative text for factual content.
- Display source context where verification matters. No fake citations or invented figures.
- Use real footage/screenshots when the task requires demonstrating reality. Label illustrative AI visuals appropriately if they could be confused for evidence.
- Give complex diagrams readable holds; do not remove the result too quickly after completing the build.
- Use varied compositions but consistent spacing, typography, line weights, colors, easing, shadows and graphic component behavior.
- Do not add sound effects merely because an object appeared; use sync and restraint.

## Timing and motion grammar (guidelines, not laws)
- Small callout entry: often 0.25–0.5 s; read hold depends on text complexity.
- Diagram components: stagger logically in speech order; use around 0.3–0.7 s for common node/line reveals if pacing allows.
- Major reveal: often 0.6–1.2 s, reserved for an important payoff.
- Keep critical text still while it must be read. Animate entry, settle, then hold; moving camera and moving text at the same time can reduce readability.
- Use blur only for sufficiently fast movement; don't smear labels or factual information.
- Use parallax only when separated layers support plausible depth. Avoid bending/distoriting faces, diagrams or UI.
- Use stronger transitions at chapter shifts, reveals or motivated visual matches, not on every cut.

## Long-form visual rhythm
- Aim for a noticeable, meaningful visual change around every 5–10 seconds during dense narration, but allow complex visuals and emotional moments to hold longer.
- Use occasional chapter-level hero graphics. Support them with smaller callouts, brief source inserts, footage, screenshots or clean holds.
- As a planning guide, at least half of major explanatory beats should be purpose-built or sourced explanatory visuals when the subject supports them. This is not a screen-time quota.
- Avoid three interchangeable AI video clips in a row when the explanatory topic changes.

## Sound design and music
- Make narration clear before layering music.
- Music supports the emotional arc and is automated/ducked by listening and metering. Do not assume one fixed level is correct for every track.
- Choose a small vocabulary of SFX: soft UI tick, restrained whoosh, light impact, low transition swell, page/camera/Foley cue or deliberate silence. Match the cue to the source and use a sound file that actually exists.
- No automatic pop on every label. No excessive sub-bass hits under normal narration. Let evidence, emotion and clear speech breathe.

## Hybrid asset pipeline
1. Build the narrative/visual map.
2. Source real visual evidence and footage where needed.
3. Build diagrams/charts/labels from exact editable assets.
4. Create illustrative images/video only for the beats that benefit from them.
5. Animate with the confirmed renderer.
6. Composite with footage and use purposeful transitions.
7. Add SFX/music after the cut's visual rhythm is coherent.
8. Preview at full size and phone scale; review silently for visual logic and listen for voice intelligibility.
9. Check rendered master, not just project/timeline, for timing, layout and artifacts.

## Output and QC
- Default landscape long-form: 1920×1080; default vertical: 1080×1920; follow explicit requests.
- Verify aspect ratio, frame rate, duration, streams/audio mapping, A/V sync, subtitles, spelling/proper nouns, source labels, chart values/scales, graphic overlap, clipping, animation artifacts, and final end frame.
- Report actual limitations and failed checks. Do not state that a graphic, effect, or render was verified unless it was examined.
